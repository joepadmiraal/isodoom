# IsoDoom

An isometric top-down remake of Doom in Godot 4 + C#. It loads the original WAD at runtime. The full design is in `docs/SPEC.md`. Read only the sections your task cites.

## Session workflow

Each session completes **one task** from `docs/TASKS.md`:

1. Read the task and the `SPEC.md` sections it cites.
2. Do the work. The task is done when its *Done when* criterion holds and all tests pass.
3. In `TASKS.md`: tick the task, and add any follow-up tasks you discovered under the right milestone.
4. When you make a design decision the spec doesn't cover, add it to the decisions log in `SPEC.md` §12.
5. Commit on a branch named after the task (e.g. `t1.2-wad-reader`).

## Commands

Run from the repo root. Versions are pinned in `docs/SPEC.md` §12; the .NET SDK comes from `global.json`.

- **Build:** `dotnet build IsoDoom.sln`
- **Test:** `dotnet test`. Tests that need a real WAD skip themselves without it (as in CI); see *Test data*.
- **Run:** `godot` opens the editor (F5 runs the main scene, currently the WAD viewer). `godot --headless --quit-after 60` runs the main scene headlessly for 60 frames; drop `--headless` for a window. On a fresh checkout, run `godot --headless --import` first.
  - Game arguments go after `--`: `godot -- -iwad wads/doom2.wad -file my.wad`. Without `-iwad` (or `ISODOOM_IWAD`), the IWAD search of `src/Wad/IwadLocator.cs` runs (saved path, working dir, `wads/`, `DOOMWADDIR`, Steam/GOG, …; SPEC §12) and a file picker opens when nothing is found. The shareware IWAD refuses `-file`, as in vanilla.
- **Level scene:** `godot -- --level E1M1` (or `--level MAP01`; IWAD as above) shows the map as a textured mesh through the game camera (T3.3: fixed iso, orthographic) instead of the viewer, and runs the sim on it (T4.7: a 35 Hz tic loop independent of the frame rate, one `ticcmd` per tic from the input, mobjs drawn interpolated between the last two tics; the camera follows the player mobj). Debug arguments: `--level-tweaks=topdown|vanilla` (the sim's tweaks and the commands built for them: twin-stick, or vanilla's facing-relative movement and turning keys; default `topdown`), `--level-aim-assist=DEG|off` (the aim assist's half-cone, 0–45°: the player's shots snap to the nearest visible target with a part within it when the facing misses, SPEC §12 T6.7; default `5` with `topdown`, off with `vanilla`), `--level-camera=iso|overview|fly` (default `iso`), `--level-projection=ortho|perspective` (the game camera's; default `ortho`, SPEC §12 T3.3), `--level-pitch=DEG` (45–60, default 55), `--level-zoom=UNITS` (view height, 320–1600, default 640), `--level-cutaway=cut|dither|off` (the wall cutaway around the player under the game camera, SPEC §12 T3.4; default `cut`), `--level-cutaway-radius=UNITS` (default 80), `--level-cutaway-height=UNITS` (the cutoff above the player's feet, default 32), `--level-cutaway-cursor=on|off` (the cursor ground point cuts too; default `off`), `--level-cutaway-things=decor|all|off` (which billboards in front of the player the cutaway cuts as walls, SPEC §12 T3.4b; default `decor`: all but actors, so monsters, barrels and the player stay whole), `--level-cutaway-cap=dark|flat|off` (a raised floor cut by the cutaway shows its flat at the cutoff, darkened or not, instead of the void inside; SPEC §12 T3.4a; default `dark`), `--level-masked-back=mirror|off` (a masked middle on one side of a line only is also drawn from behind, mirrored; `off` = vanilla, one side only; SPEC §12 T3.1a; default `mirror`), `--level-view=top` (the overview camera straight down; default iso), `--level-focus=SECTOR`, `--level-tiling=size` (default `vanilla`), `--level-sector-floor=SECTOR:HEIGHT[,…]`, `--level-skill=1-5` (whose things are drawn as billboards, T3.5; default 3), `--level-monsters=on|off` (`off` spawns no monsters, vanilla's `-nomonsters`; T5.7), `--level-sprite-tilt=0-1|off|half|full` (billboards turn towards the camera by this fraction of its elevation, SPEC §12 T3.6; default `full`), `--level-sprite-tilt-depth=upright|tilted` (default `upright`: a tilted billboard sorts as an upright one), `--level-sprite-shadow=off|blend|dither` (blob shadows under actors; default `off`), `--level-sprite-outline=off|INDEX` (a one-texel outline in palette index INDEX; default `0`, black), `--level-sprite-wall-pull=UNITS|off` (billboards are pulled towards the camera by the thing's radius, at most UNITS, so a wall the thing stands against behind it does not cut it, SPEC §12 T3.5a; default `16`), `--level-sprite-hidden=depth|upright` (with `upright`, a tilted billboard is also dropped whole when the level would hide its upright billboard whole, so monsters behind a wall no longer show their heads above it; costs about 3 ms a frame under lavapipe; SPEC §12 T3.6a; default `depth`), `--level-hud=bar|full|off` (T6.11, under the game camera: vanilla's status bar scaled at the bottom, the game camera's focus kept above it, or the minimal fullscreen HUD, or none; the message line shows at the top left with all three; default `bar`), `--level-hud-scale=N|auto` (default `auto`: the largest whole scale vanilla's 320×200 screen fits, 4 at 1280×800), `--level-player-light=LEVEL|off` (the player's own sprite is lit as if its sector's light were at least LEVEL, 0–255, so it stays visible in dark sectors; SPEC §12 T4.7a; default `128`), `--level-fuzz=on|off` (things with `MF_SHADOW`, spectres and the player with the blur sphere, drawn with the fuzz, vanilla's `R_DrawFuzzColumn` approximated; `off` draws them as any sprite; SPEC §12 T6.9; default `on`), `--level-weapon-light=on|off` (the player's weapon flash, `extralight` 1–2, lights the whole level one or two light levels up, as vanilla's lights the view; the flash frame of the player's sprite is full bright either way; SPEC §12 T6.6; default `on`), `--level-palette-effects=on|off` (the player's palette flashes, red for damage, gold for pickups, green in the radiation suit, and the invulnerability and light amplification colormaps; SPEC §12 T6.8; default `on`), `--level-light=player|none|camera` (light diminishing, SPEC §12 T2.8; default `player`), `--level-light-origin=X,Y` (the player position for it, map units; default the free-fly pivot or the player mobj), `--level-light-near=UNITS` (player mode's shortest distance, default 80; 0 = the tables down to the player, T3.7), `--level-light-reference=UNITS` (none mode's distance, default 128), `--level-background=RRGGBB` (the void's colour; one in no palette, e.g. `00ff00`, makes cracks stand out), and `--level-screenshot=FILE.png` (capture and quit; needs a real renderer, e.g. the offscreen Xvfb + lavapipe command below; never commit the images).
  - **Level scene keys:** Tab cycles the game camera, the overview and the free-fly debug camera, Home puts the player (in free-fly the camera) at player 1's start, PgDn/PgUp load the next/previous map of the WAD, L cycles the light diminishing mode, X cycles the cutaway style (cut, dither, off), V the things it cuts (decor, all, off), T the sprite tilt (full, half, off), G the blob shadows (off, blend, dither), P the sprite wall pull (on, off), H the sprite upright hiding (depth, upright), B the player's minimum light (on, off), M the one-sided masked middles from behind (mirrored, off), K the cutaway cap (dark, flat, off), = and - the HUD (as vanilla's screen size keys: bar, fullscreen HUD, none), F1 lists the controls, F3 hides the overlay (map, FPS, camera position in map units, the sector and subsector under the camera; with the game camera the player mobj (position, angle, state, sector), the tic, checksum and last `ticcmd`, and the cursor ground point, also marked by a ring; the player's health, armor, keys, powers and kills/items/secrets, its weapon (and the pending one), the weapons owned and the ammo, its last message for 4 s, and the HUD's mode and face; the HUD itself, T6.11: the status bar and the message line, shows under the game camera; and the sounds the sim started in the last second as `NAME@ORIGIN`, silent until M7, T6.10). An exit (switch, walk line, E1M8's floor) loads the next map in the same game, without an intermission (T5.8; secret exits as vanilla: E1M3 → E1M9 → E1M4); the game's end (ExM8, MAP30) or a next map the WAD lacks stops the world with a line in the overlay. Game camera: the input actions build each tic's `ticcmd`, only while it is current: W/A/S/D (or the left stick) walk the player relative to the screen (Shift runs, the left-stick click toggles run; these are input actions in `project.godot`, T4.6), the mouse (or the right stick) aims, the left button (or RT) fires (T6.6: vanilla's psprites run the weapon, unseen), 1–8 pick a weapon slot as vanilla's keys and the wheel (or LB/RB) the next/previous weapon owned (Chocolate Doom's order), E/Space use (with the use fallback, SPEC §12 T5.2; until M5 ports their effects, the specials that use and walk-over lines trigger print as `Level: tic N: EV_… (not ported yet)`), Ctrl+wheel zooms, O = orthographic/perspective. Free-fly: click to capture the mouse (Esc releases), mouse look, W/A/S/D move, E/Space up, Q/C down, Shift ×4, Alt ×¼, wheel = speed, Ctrl+wheel = FOV or ortho size, O = perspective/orthographic.
  - **Scripted input** (no keyboard needed): `--level-script="click; look 0 200; hold W 60; tap PageDown; print; shot FILE.png"` feeds the commands through `Input.ParseInputEvent` and quits (full list in `src/Game/LevelScript.cs`); put `--fixed-fps 60` before `--` for frame-exact movement. `mouse X Y` moves the cursor (viewport pixels; the headless viewport is 64×64) and `place X Y [ANGLE]` puts the player mobj at a map point (on the floor, no momentum, no collision check). `ticcmd [vanilla]` prints the `ticcmd` the builder (T4.6, `src/Game/TiccmdBuilder.cs`) makes from the input since the last tic for the player, with the twin-stick tweaks or vanilla's. **Tic scripting** (T4.7): `cmd FORWARD SIDE ANGLETURN [BUTTONS] [TICS]` queues raw `ticcmd`s (twin-stick: ANGLETURN = absolute angle × 65536 / 360, FORWARD thrusts north, SIDE east), `step TICS` runs TICS tics built from the input (keys held with `down`), `checksum` prints `leveltime`, `World.Checksum()` and the player mobj; with either in the script tics run only from the queue (35 Hz, the world holds still when it is empty), so `godot --headless --fixed-fps 30 -- --level E1M1 --level-script="cmd 50 0 16384 0 35; down W; step 35; up W; checksum"` prints the same checksum at any `--fixed-fps` (`sim live|scripted` switches, `tics N` waits N tics, `smooth FRAMES` prints the drawn player's step per frame). `visible [MIN]` prints how much of the player the game camera shows (% of its pixels; the script fails below MIN, default 25; needs a real renderer), `walkto X Y [STEP] [MIN]` moves the player in a straight line through walls checking that at every STEP units, and `tour [STEP] [MIN]` walks it to every sector's floor (T3.4: `--level-script="tour 32"` on E1M1 takes about a minute under lavapipe). `plane SECTOR floor|ceiling HEIGHT [SPEED]` moves a sector's plane through the sim after each tic, as a mover would (T5.1, a debug move until doors and lifts exist; tics must run: `sim live` or queued), and `smooth FRAMES SECTOR` prints how evenly it is drawn (`smooth FRAMES` does the player). `map NAME` waits for the queued tics and fails the script unless the scene shows map NAME (T5.8: `--level E1M1 --level-script="place 2940 -4768 180; cmd 0 0 -32768 0 2; cmd 0 0 -32768 2; map E1M2"` uses DOOM1's exit switch). `fov vanilla; view X Y ANGLE` puts the free-fly camera where a vanilla player standing at map point X, Y facing ANGLE (degrees) would see (eye level, vanilla's 90° field in a 16:10 window), for comparing with vanilla screenshots (with `--level-light=camera`). `power NAME [TICS]` gives the player a power-up as its pickup does (`invulnerability`, `strength`, `invisibility`, `ironfeet`, `allmap`, `infrared`) and `flash damage|bonus COUNT` sets its palette flash, before the next tic (T6.8; e.g. `power infrared; cmd 0 0 0 0 1; tics 1; shot FILE.png`). `spawn TYPE X Y [ANGLE]` spawns a mobj of `MT_TYPE` on the floor before the next tic (T6.9: e.g. `power invisibility; spawn shadows 1120 -3560 225; cmd 0 0 16384 0 1; shot FILE.png` on E1M1 shows the fuzz on the player and a spectre). `joy AXIS VALUE` / `joybutton BUTTON down|up` inject gamepad input (Godot `JoyAxis`/`JoyButton` names: `LeftX`/`LeftY` move, `RightX`/`RightY` aim, `TriggerRight` fires, `A` uses, `LeftStick` toggles run; T4.9), and `tictime TICS` times `World.G_Ticker` over the next TICS tics (SPEC §9's 2 ms budget; e.g. `--level E1M9 --level-skill=4 --level-script="joy LeftY -1; sim live; wait 120; tictime 700"`). `missile [TYPE]` (T6.5) makes the player fire a missile (`P_SpawnPlayerMissile`, default `rocket`; e.g. `troopshot`, `bruisershot`) along its facing before the next tic, e.g. `--level-tweaks=vanilla --level-script="place 840 -3490 150; missile troopshot; cmd 0 0 0 0 12; tics 12; shot FILE.png"`. `route FILE [TICS]` (T5.10) plays a `.route` file (only its first TICS tics with TICS, T6.11, so `tics TICS; shot FILE.png` captures that exact tic) (`tests/IsoDoom.Tests/Sim/Routes/`) through the game loop. It needs `--level-tweaks=vanilla --level-monsters=off` (`on` for a route with the `monsters` header, whose `damage`/`alert`/`rocket` events run before their tics, T6.4) and the route's map and skill, and it does not wait, so `tics N; shot FILE.png` can follow. `map NAME [EXITS]` waits for the queued tics and fails unless the scene shows NAME (after EXITS exits), e.g. `godot --headless --fixed-fps 35 -- --level E1M1 --level-tweaks=vanilla --level-monsters=off --level-script="route tests/IsoDoom.Tests/Sim/Routes/e1m1-exit.route; map E1M2 1"`.
- **Viewer check:** `godot --headless -- --viewer-check` walks every graphic and every lump in the viewer and checks the uploads; it exits 1 on a failure. With a real renderer it also compares every drawn pixel: run it windowed, or offscreen with `WAYLAND_DISPLAY= VK_DRIVER_FILES=/usr/share/vulkan/icd.d/lvp_icd.json xvfb-run -a -s "-screen 0 1280x720x24" godot -- --viewer-check`. Add `--viewer-screenshots=DIR` to save captures (never commit WAD-derived images).
- **Level check:** `godot --headless -- --level-check` loads every map of the IWAD in the level scene and checks the meshes, texture binding, per-sector data and thing billboards against the levels, plus a floor moved through the data texture, a sector moved in the sim drawn at its interpolated heights, and a wall texture (a switch's other texture where it has one) and a floor flat changed at run time (T5.1), and where a map has a usable teleport line the player run across it (drawn where it lands, the camera snap asked for, fog at both ends; T5.6); it exits 1 on a failure. With a real renderer (windowed, or offscreen as the viewer check) it also renders one map (`--level MAP`, default `E1M1`/`MAP01`) top-down, side-on at every axis-aligned wall (masked middles over their whole opening: texels, holes and the rows outside the texture), obliquely at the moved floor, side-on at the wall whose texture changed at run time, and the cutaway from the game camera's angle (a centre just behind and just in front of a tall wall, and just behind a raised floor: cut pixels show the background, or with the cap the raised floor's flat at the cutoff, the rest draw as with the cutaway off) and the things (each distinct sprite frame, rotation and mirror side-on, alone, with the outline; one as the player's own sprite in a dark sector, at its minimum light; one without outline, and two with full tilt from the game camera's pitch, again 1:1; one from the game camera's angle over the floor; one moved in front of a wall, whose full-tilt billboard the wall must not cut; the widest one against a wall behind it, which the wall pull must keep whole, and behind a wall, which must still hide it; one behind a wall taller than it, whose tilted billboard peeks over the wall unless the upright hiding drops it, and partly hidden and in front, which the upright hiding must leave as they are; the tallest one with a cut centre behind it, behind and below it, and in front of it, cut as a decoration and kept as an actor), a thing fuzzed in front of another (T6.9, every pixel against the CPU fuzz), and the HUD (T6.11: the status bar, the fullscreen HUD and the message line scaled over the view, every pixel against the palette), and compares drawn pixels with the CPU texel lookup and light mapping; on every map it also runs the status bar's tic (face, keys, ammo, the message line), and on every map with a use exit (special 11) it also uses it and checks that the scene goes on to the next map in the same world (T5.8) (about 30 s for DOOM1 E1M1 under lavapipe, 4 s for the synthetic IWAD). It also fails a map that takes over 1 s to load (SPEC §9) and prints the slowest.
- **Vanilla comparison:** `tools/VanillaRef/compare.sh DIR wads/DOOM1.WAD E1M1 "1056 -3616 90;1056 -3616 0" [--images]` renders each view (map X Y, angle in degrees, at eye level; walls, floors and masked middles, no sprites, ceilings or sky; the map's lights, no animations, unless `--tic N` after the views: both then run N tics from the start without monsters and render with the light specials, animated textures and scrolling walls of that tic, T5.7) with vanilla's renderer (doomgeneric, GPL-2.0, pinned and patched by `tools/VanillaRef/build.sh` into `~/.cache/isodoom/vanilla-ref`; a dev tool, never shipped) and in the level scene offscreen, and compares them pixel by pixel (SPEC §12, T2.9). DIR gets WAD-derived images: keep it out of the repo.
- **Vanilla movement routes:** `tools/VanillaRef/routes.sh [ROUTE.route...]` plays each `ticcmd` route of `tests/IsoDoom.Tests/Sim/Routes` (default all; text format in `VanillaRoute.cs`) in the vanilla reference as a v1.9 demo (no monsters; every special runs) and writes its per-tic dump (one line per tic: the player, sector heights and lights, switched textures, fogs, health/armor/keys/secrets, the inventory, a hash of every mobj's state (T6.1), the powers and the palette vanilla's `ST_doPaletteStuff` picks (T6.8), the weapon and its psprites (T6.6), every `S_StartSound` call and `P_RemoveMobj`'s `S_StopSound` (T6.10), the HUD after `ST_Ticker`/`HU_Ticker` (T6.11: the status bar's face, keys and ammo, the message line, and a hash of every pixel both draw) and the exit, see `VanillaRoute.cs`; a route with `exit normal|secret` must leave the level on its last tic, T5.9; a `monsters` header plays it with monsters, and `damage X Y AMOUNT` / `alert` / `rocket` lines between the ticcmds hurt the thing spawned at X, Y, make a noise as player 1's shot would, or (T6.5) fire a rocket (`P_SpawnPlayerMissile`), before the next tic, standing in for the weapons until T6.6, T6.4): beside the route for the synthetic IWAD's (commit those), to `$ISODOOM_VANILLA_ROUTES` (default `~/.cache/isodoom/vanilla-routes`) for DOOM1.WAD's (never commit them). Needs DOOM1.WAD for both. `dotnet test` (`VanillaRouteTests`) compares the sim with them tic by tic; DOOM1.WAD's routes skip without the WAD or the dump (SPEC §12 T4.8).
- **Vanilla HUD comparison:** `tools/VanillaRef/hud.sh DIR tests/IsoDoom.Tests/Sim/Routes/e1m1-weapons.route "333,556,690" [--images]` plays a DOOM1 route in the vanilla reference (dump.c writes the status bar and message line of those tics: `DUMP_HUD_DIR`/`DUMP_HUD_TICS`) and in the level scene offscreen (1280×800, `route FILE TIC; tics TIC; shot`), and compares the HUD pixels (T6.11). DIR gets WAD-derived images: keep it out of the repo. `ISODOOM_HUD_DIR=DIR ISODOOM_HUD_TICS=N,M dotnet test` also writes the sim's HUD images of every route (`ROUTE-simhudN.ppm`).
- **Route generator:** `dotnet run --project tools/RouteGen -- NAME [OUT.route]` writes the route NAME (a steering script in `tools/RouteGen/Program.cs`; default `tests/IsoDoom.Tests/Sim/Routes/NAME.route`) by steering the sim: A* over `P_CheckPosition`, manual doors opened on the way (locked ones once their key is held), the ticcmds replayed in a fresh world as a check (T5.5; a dev tool, never shipped). Then run `routes.sh` on it. `e1m1-exit` … `e1m9-exit` and `e1m3-secret-exit` reach each DOOM1 exit (T5.9); `e1m1-monsters`, `e1m2-monsters`, `e1m8-demons`, `e1m8-barons`, `e1m8-nightmare` and `synthetic-monsters` fight monsters with route events (`Gunner.cs`: each monster is shot once it attacked; T6.4); `testmap-weapons` (every shareware weapon) and `e1m1-weapons` (`Gunner.Guns`) fire the player's own weapons with `BT_ATTACK` and change them with `BT_CHANGE` (T6.6; `Steer.Fire`, `FireAt`, `Change`). To write a script, `-- --info MAP [S1,S2,…]` prints DOOM1 MAP's start, special lines, tagged sectors, keys and solid things (with sectors: their heights, box, lines and neighbours), `-- --probe MAP "X,Y;X,Y"` whether the player fits at those points, and `-- --monsters MAP [SKILL]` the monsters and barrels spawned (their spawn points are what `damage X Y` names).
- **Synthetic IWAD:** `dotnet run --project tools/SyntheticIwad -- OUT.wad` writes a small IWAD of generated, non-id content covering every lump kind; CI runs the viewer check against it. Its `E1M1` covers the wall-section cases; `E1M2` is M5's specials map, to which each M5 task adds its cases (render checks run on `E1M1`; T5.1a).
- **Export (Linux x86_64):** `mkdir -p export/linux && godot --headless --export-release "Linux" export/linux/IsoDoom.x86_64`. Needs the 4.7.2 .NET export templates in `~/.local/share/godot/export_templates/4.7.2.stable.mono/` (build the dev container with `INSTALL_EXPORT_TEMPLATES=true`, or see `.github/workflows/ci.yml`). Smoke test: `export/linux/IsoDoom.x86_64 --headless --quit-after 60`.
- **CI:** `.github/workflows/ci.yml` runs build + test, generates the synthetic IWAD, runs the viewer and level checks in the editor (headless), exports and smoke-tests the Linux build, runs both checks on the exported build under Xvfb + lavapipe, and uploads `export/linux/` as the `IsoDoom-linux-x86_64` artifact. Lint it with `actionlint` (in the dev container; it runs `shellcheck` on the scripts).

## Invariants

- **`Sim/` is deterministic** (so lockstep co-op is possible later):
  - pure C#, with no Godot types;
  - fixed-point/BAM maths only, no `float`/`double`;
  - no `System.Random`, wall-clock time, or iteration over `Dictionary`/`HashSet`;
  - the only input is a `ticcmd` per player per tic.

  The presentation layer converts to floats.
- **WAD data stays out of the repo.** All assets load from the user's WAD at runtime. `wads/` is gitignored.
- **Ported vanilla logic keeps vanilla names** (`P_Random`, `A_Chase`, `mobjinfo`), with a comment citing the source file (e.g. `// p_enemy.c`). This keeps it easy to diff against the original.
- **Deviations from vanilla behaviour sit behind a named tweak flag** (SPEC §6.3), so pure vanilla behaviour stays testable.
- **The license is GPL-2.0-or-later.** Porting id Software or Chocolate Doom code is fine. Check license compatibility before adding any other dependency.
