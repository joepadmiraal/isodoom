# IsoDoom

An isometric top-down remake of Doom in Godot 4 + C#. It loads the original WAD at runtime. The full design is in `docs/SPEC.md`. Read only the sections your task cites.

## Session workflow

Each session completes **one task** from `docs/TASKS.md`:

1. Read the task and the `SPEC.md` sections it cites.
2. Do the work. The task is done when its *Done when* criterion holds and all tests pass.
3. In `TASKS.md`: tick the task, and add any follow-up tasks you discovered under the right milestone.
4. When you make a design decision the spec doesn't cover, add it to the decisions log in `SPEC.md` §12.
5. Commit on a branch named after the task (e.g. `t1.2-wad-reader`).

## Commands

Run from the repo root. Versions are pinned in `docs/SPEC.md` §12; the .NET SDK comes from `global.json`.

- **Build:** `dotnet build IsoDoom.sln`
- **Test:** `dotnet test`. Tests that need a real WAD skip themselves without it (as in CI); see *Test data*.
- **Format:** `dotnet format IsoDoom.sln` formats the code to `.editorconfig` (the Godot C# style guide over .NET's conventions; vanilla names stay, SPEC §12 Q3); `dotnet format IsoDoom.sln --verify-no-changes --severity warn` checks it, as CI does, naming included (Q4: `IDE1006` at warning; `dotnet format` reports a misnamed symbol but cannot rename it: rename it in the IDE). The one-time reformat is in `.git-blame-ignore-revs`: `git config blame.ignoreRevsFile .git-blame-ignore-revs` hides it from `git blame`.
- **Run:** `godot` opens the editor (F5 runs the main scene: the game, T7.1, at the title loop; with `--viewer` after `--`, the WAD viewer). `godot --headless --quit-after 60` runs the main scene headlessly for 60 frames; drop `--headless` for a window. On a fresh checkout, run `godot --headless --import` first.
  - Game arguments go after `--`: `godot -- -iwad wads/doom2.wad -file my.wad`. Without `-iwad` (or `ISODOOM_IWAD`), the IWAD search of `src/Wad/IwadLocator.cs` runs (saved path, working dir, `wads/`, `DOOMWADDIR`, Steam/GOG, …; SPEC §12) and, with a display and no `--level*` argument, the IWAD menu (T7.2, `src/Game/IwadMenu.cs`) shows before the game when it finds several IWADs (pick one with the keyboard, mouse or pad; it is saved and comes first next time) or none (browse with the file picker). The shareware IWAD refuses `-file`, as in vanilla.
- **Game scene** (the level scene, T7.1): without `--level` it starts at the title loop (d_main.c's: `TITLEPIC`, `CREDIT`, `HELP2` for vanilla's tics, no demos); any key, mouse button or pad button there opens the menu (T7.2: m_menu.c's, `src/Game/MMenu.cs`; Escape or the pad's Start open and close it anywhere: New Game → episode → skill, Options, Load/Save (T7.6: six slots; a pad's A on an empty slot fills in the map and its time; F6 quicksaves, picking a slot the first time, F9 quickloads), Read This!, Quit; arrows, Enter, Backspace, letters and y/n, or the D-pad/left stick, A (yes) and B (no), or the mouse: hover, left click, right click back, wheel; the world holds under it). An exit goes through the intermission (a placeholder until T7.4: the stats at once, fire or use go on, then vanilla's 4 s "entering", or fire or use again) to the next map; an episode's end (ExM8) shows the finale (a placeholder until T7.5: the episode's flat, a stand-in text, then the end picture, which stays, as vanilla's, until the menu starts or ends a game), Doom II's text screens come after maps 6, 11, 20 and the secret exits of 15 and 31 (any button after 50 tics goes on), and MAP30 or a next map the WAD lacks ends the game at the title loop with a line in the overlay. **Saves** (T7.6, `src/Game/SaveGame.cs`, `src/Sim/World.SaveG.cs`): our own format, exact (a loaded game goes on with the saved game's checksums; not vanilla's files), in `user://savegames/IWAD/isodoomsavN.dsg` (`--savedir=DIR`; headless runs, the checks, scripts and screenshots use a temporary directory of their own); a save goes with the next tic (`BTS_SAVEGAME`), a load melts; one from another version, damaged or another game's is refused with a message. Pause (or the pad's Back) pauses through the `ticcmd` (vanilla's `BTS_PAUSE`; `M_PAUSE` shows), and so does losing the window's focus (not under a script or the checks). Each game state change (and a level loaded over a level: a reborn, a new game) melts the screen as vanilla's (T7.1a: f_wipe.c's melt over the whole window, about a second, the game holding still meanwhile; Options → More Options → Video → Screen Wipe, or `--level-wipe=melt|off`).
- **Options and settings** (T7.3, `src/Game/Settings.cs`, `LevelScene.Settings.cs`): Options → More Options… (the menu font's text pages, `MMenu.Setup.cs`) has Controls (mouse sensitivity; the game's and the menus' input actions: Enter, A or a click waits for a key, mouse button or pad input to bind, Escape cancels, Delete clears the keyboard's and mouse's bindings, the pad's X the pad's; Reset Controls), Video (window size, fullscreen, vsync, frame cap, zoom, pitch, projection), Gameplay (aim assist, the cutaway's style, things, cap, radius and cursor, light diminishing, door lids, masked backs, weapon light, palette flashes), Sprites (tilt, tilt depth, shadows, outline, wall pull, upright hiding, player light, fuzz), HUD (screen, scale, messages, detail), Sound (the volumes and the music chip, OPL3 or OPL2: T7.8g, switched at once, the song again from its start; `--level-opl=opl3|opl2`) and Reset All; left/right (or Enter) step a value. Every change applies at once and is saved to `user://settings.cfg` (only values that differ from the defaults; the bindings as `controls/ACTION = "key:87 padaxis:1-"`, Godot's codes), with vanilla's options and the debug keys' and Ctrl+wheel's changes. A `--level-*` argument overrides its setting for the run without saving it (until it is changed). `--settings=FILE|off` picks the file; headless runs, the checks, `--level-script` and `--level-screenshot` run on the defaults and save nothing unless `--settings=FILE` is given. The volumes set the `Sfx` and `Music` audio buses; the mouse sensitivity scales vanilla's mouse turning (`--level-tweaks=vanilla`: the mouse turns, g_game.c's `mousex`); the debug keys leave a key bound to a game action alone.
- **Level scene:** `godot -- --level E1M1` (or `--level MAP01`; IWAD as above) starts a new game on that map instead of the title loop (vanilla's `-warp`, without its melt), showing the map as a textured mesh through the game camera (T3.3: fixed iso, orthographic), and runs the sim on it (T4.7: a 35 Hz tic loop independent of the frame rate, one `ticcmd` per tic from the input, mobjs drawn interpolated between the last two tics; the camera follows the player mobj). T5.7), `--level-sprite-tilt=0-1|off|half|full` (billboards turn towards the camera by this fraction of its elevation, SPEC §12 T3.6; default `full`), `--level-sprite-tilt-depth=upright|tilted` (default `upright`: a tilted billboard sorts as an upright one), `--level-sprite-shadow=off|blend|dither` (blob shadows under actors; default `off`), `--level-sprite-outline=off|INDEX` (a one-texel outline in palette index INDEX; default `0`, black), `--level-sprite-wall-pull=UNITS|off` (billboards are pulled towards the camera by the thing's radius, at most UNITS, so a wall the thing stands against behind it does not cut it, SPEC §12 T3.5a; default `16`), `--level-sprite-hidden=depth|upright` (with `upright`, a tilted billboard is also dropped whole when the level would hide its upright billboard whole, so monsters behind a wall no longer show their heads above it; costs about 3 ms a frame under lavapipe; SPEC §12 T3.6a; default `depth`), `--level-hud=bar|full|off` (T6.11, under the game camera: vanilla's status bar scaled at the bottom, the game camera's focus kept above it, or the minimal fullscreen HUD, or none; the message line shows at the top left with all three; default `bar`), `--level-hud-scale=N|auto` (default `auto`: the largest whole scale vanilla's 320×200 screen fits, 4 at 1280×800), `--level-player-light=LEVEL|off` (the player's own sprite is lit as if its sector's light were at least LEVEL, 0–255, so it stays visible in dark sectors; SPEC §12 T4.7a; default `128`), `--level-fuzz=on|off` (things with `MF_SHADOW`, spectres and the player with the blur sphere, drawn with the fuzz, vanilla's `R_DrawFuzzColumn` approximated; `off` draws them as any sprite; SPEC §12 T6.9; default `on`), `--level-weapon-light=on|off` (the player's weapon flash, `extralight` 1–2, lights the whole level one or two light levels up, as vanilla's lights the view; the flash frame of the player's sprite is full bright either way; SPEC §12 T6.6; default `on`), `--level-palette-effects=on|off` (the player's palette flashes, red for damage, gold for pickups, green in the radiation suit, and the invulnerability and light amplification colormaps; SPEC §12 T6.8; default `on`), `--level-light=player|none|camera` (light diminishing, SPEC §12 T2.8; default `player`), `--level-light-origin=X,Y` (the player position for it, map units; default the free-fly pivot or the player mobj), `--level-light-near=UNITS` (player mode's shortest distance, default 80; 0 = the tables down to the player, T3.7), `--level-light-reference=UNITS` (none mode's distance, default 128), `--level-background=RRGGBB` (the void's colour; one in no palette, e.g. `00ff00`, makes cracks stand out), `--level-wipe=melt|off` (the screen wipe at each game state change, T7.1a; default `melt`), `--level-fullscreen=off|on|exclusive` (the window: borderless fullscreen, exclusive, or a window of the Video page's size; default `on`, but `off` under `--level-script` and `--level-screenshot`, whose captures are the window's size), and `--level-screenshot=FILE.png` (capture and quit; needs a real renderer, e.g. the offscreen Xvfb + lavapipe command below; never commit the images).
  - **Level scene keys:** Tab cycles the game camera, the overview and the free-fly debug camera, Home puts the player (in free-fly the camera) at player 1's start, PgDn/PgUp load the next/previous map of the WAD, L cycles the light diminishing mode, X cycles the cutaway style (cut, dither, off), V the things it cuts (decor, all, off), T the sprite tilt (full, half, off), G the blob shadows (off, blend, dither), P the sprite wall pull (on, off), H the sprite upright hiding (depth, upright), B the player's minimum light (on, off), M the one-sided masked middles from behind (mirrored, off), K the cutaway cap (dark, flat, off), J the door lids (on, off), = and - the HUD (as vanilla's screen size keys: bar, fullscreen HUD, none), Pause the pause (T7.1), F1 lists the controls, F3 hides the overlay (map, FPS, the game state (T7.1: level, intermission, finale or the title loop's page, paused) and `gametic`, camera position in map units, the sector and subsector under the camera; with the game camera the player mobj (position, angle, state, sector), the tic, checksum and last `ticcmd`, and the cursor ground point, also marked by a ring; the player's health, armor, keys, powers and kills/items/secrets, its weapon (and the pending one), the weapons owned and the ammo, its last message for 4 s, and the HUD's mode and face; the HUD itself, T6.11: the status bar and the message line, shows under the game camera; and the sounds the sim started in the last second as `NAME@ORIGIN`, silent until M7, T6.10). An exit (switch, walk line, E1M8's floor) loads the next map in the same game after the intermission (T5.8, T7.1; secret exits as vanilla: E1M3 → E1M9 → E1M4); the game's end (ExM8's finale, MAP30) or a next map the WAD lacks goes back to the title loop with a line in the overlay. A dead player turns towards its killer as vanilla (unseen under the iso camera) and use reborns it: the map reloads with a fresh player (T6.12). Game camera: the input actions build each tic's `ticcmd`, only while it is current: W/A/S/D (or the left stick) walk the player relative to the screen (Shift runs, the left-stick click toggles run; these are input actions in `project.godot`, T4.6), the mouse (or the right stick) aims, the left button (or RT) fires (T6.6: vanilla's psprites run the weapon, unseen), 1–8 pick a weapon slot as vanilla's keys and the wheel (or LB/RB) the next/previous weapon owned (Chocolate Doom's order), E/Space use (with the use fallback, SPEC §12 T5.2; until M5 ports their effects, the specials that use and walk-over lines trigger print as `Level: tic N: EV_… (not ported yet)`), Ctrl+wheel zooms, O = orthographic/perspective. Free-fly: click to capture the mouse (Esc releases), mouse look, W/A/S/D move, E/Space up, Q/C down, Shift ×4, Alt ×¼, wheel = speed, Ctrl+wheel = FOV or ortho size, O = perspective/orthographic.
  - **Scripted input** (no keyboard needed): `--level-script="click; look 0 200; hold W 60; tap PageDown; print; shot FILE.png"` feeds the commands through `Input.ParseInputEvent` and quits (full list in `src/Game/LevelScript.cs`); put `--fixed-fps 60` before `--` for frame-exact movement. `mouse X Y` moves the cursor (viewport pixels; the headless viewport is 64×64) and `place X Y [ANGLE]` puts the player mobj at a map point (on the floor, no momentum, no collision check). `ticcmd [vanilla]` prints the `ticcmd` the builder (T4.6, `src/Game/TiccmdBuilder.cs`) makes from the input since the last tic for the player, with the twin-stick tweaks or vanilla's. **Tic scripting** (T4.7): `cmd FORWARD SIDE ANGLETURN [BUTTONS] [TICS]` queues raw `ticcmd`s (twin-stick: ANGLETURN = absolute angle × 65536 / 360, FORWARD thrusts north, SIDE east), `step TICS` runs TICS tics built from the input (keys held with `down`), `checksum` prints `leveltime`, `World.Checksum()` and the player mobj; with either in the script tics run only from the queue (35 Hz, the world holds still when it is empty), so `godot --headless --fixed-fps 30 -- --level E1M1 --level-script="cmd 50 0 16384 0 35; down W; step 35; up W; checksum"` prints the same checksum at any `--fixed-fps` (`sim live|scripted` switches, `tics N` waits N tics, `smooth FRAMES` prints the drawn player's step per frame). `visible [MIN]` prints how much of the player the game camera shows (% of its pixels; the script fails below MIN, default 25; needs a real renderer), `walkto X Y [STEP] [MIN]` moves the player in a straight line through walls checking that at every STEP units, and `tour [STEP] [MIN]` walks it to every sector's floor (T3.4: `--level-script="tour 32"` on E1M1 takes about a minute under lavapipe). `plane SECTOR floor|ceiling HEIGHT [SPEED]` moves a sector's plane through the sim after each tic, as a mover would (T5.1, a debug move until doors and lifts exist; tics must run: `sim live` or queued), and `smooth FRAMES SECTOR` prints how evenly it is drawn (`smooth FRAMES` does the player). `map NAME` waits for the queued tics and fails the script unless the scene shows map NAME (T5.8: `--level E1M1 --level-script="place 2940 -4768 180; cmd 0 0 -32768 0 2; cmd 0 0 -32768 2; skip; map E1M2"` uses DOOM1's exit switch; the scene shows the map left until the intermission is over). **Game states** (T7.1): queued tics run in every state (the title loop, the intermission, the finale: there a `cmd`'s buttons are the player's, e.g. `cmd 0 0 0 2` uses; `cmd 0 0 0 129` toggles the pause); `newgame [SKILL [EPISODE [MAP]]]` starts a new game (`G_DeferedInitNew`, as the menus' skill choice; default `--level-skill`'s, episode 1, map 1), `title` goes back to the title loop, `gamestate level|intermission|finale|demoscreen` waits for the queued tics and fails unless the game is in that state, and `skip [TICS]` presses and releases use a tic at a time until the intermission or finale is over or the finale's end picture shows (fails after TICS tics, default 3000): `godot --headless --fixed-fps 35 -- --level-script="gamestate demoscreen; newgame; map E1M1"`. While a wipe melts (T7.1a) no tic runs and queued tics wait; `wipe STEP [N]` holds the melt under way (or the next, or with N the scene's wipe number N) at melt step STEP so `shot` captures it, and `wipe` lets it go on and waits until it is over (`--level-script="newgame; wipe 12; shot FILE.png; wipe"`); `wipehold STEP [N]` sets the hold without waiting, before queueing the tics that start the wipe (queueing takes frames, in which the melt runs on). The menus (T7.2) take the script's keys, pad and mouse as a person's (`tap Escape`, `tap Enter`, `tap Down`, `tap Y`, `joybutton A down`, `joybutton DpadDown down`, `mouse X Y; click`: `click` and `rclick`, the right button, press at the last `mouse` point), and `menu [NAME [ITEM]]` prints what they show after a frame and fails unless it is NAME (`closed`, `message`, `main`, `episode`, `skill`, `options`, `sound`, `load`, `save`, `readthis1`, `readthis2`; T7.3: `setup`, `video`, `gameplay`, `sprites`, `hud`, `soundsetup`, `controls`, `movement`, `actions`, `menukeys`, and `binding` while one waits for an input) with the skull on ITEM: `--level-script="tap Escape; tap Enter; tap Enter; menu skill 2; tap Enter; gamestate level; map E1M1"` (DOOM1). **Settings** (T7.3): `setting KEY` prints one (`gameplay/cutaway`, `controls/attack`, …), `setting KEY VALUE` changes it as the menu does, `checksetting KEY VALUE` fails unless it is VALUE, `settings` prints them all; with `--settings=FILE` they are saved there, so a second run checks them: `--settings=/tmp/s.cfg --level-script="tap Escape; tap O; tap Enter; tap O; tap Enter; tap G; tap Enter; tap Right; checksetting gameplay/aim_assist 6"`, then `--settings=/tmp/s.cfg --level-script="checksetting gameplay/aim_assist 6"`. **Saves** (T7.6): `save SLOT [DESCRIPTION]` waits for the queued tics and saves at once (fails unless it saved), `load SLOT [refused]` waits for them and loads the slot (dropping the queued tics; fails if refused, or with `refused` unless refused); a script saves to a temporary directory unless `--savedir=DIR`: `--level E1M1 --level-tweaks=vanilla --level-monsters=off --level-script="route tests/IsoDoom.Tests/Sim/Routes/e1m1-exit.route 300; ## Invariants

- **`Sim/` is deterministic** (so lockstep co-op is possible later):
  - pure C#, with no Godot types;
  - fixed-point/BAM maths only, no `float`/`double`;
  - no `System.Random`, wall-clock time, or iteration over `Dictionary`/`HashSet`;
  - the only input is a `ticcmd` per player per tic.

  The presentation layer converts to floats.
- **WAD data stays out of the repo.** All assets load from the user's WAD at runtime. `wads/` is gitignored.
- **Ported vanilla logic keeps vanilla names** (`P_Random`, `A_Chase`, `mobjinfo`), with a comment citing the source file (e.g. `// p_enemy.c`). This keeps it easy to diff against the original. The naming rules skip the ported files listed at the end of `.editorconfig` (all of `src/Sim` but its few files of our own); elsewhere a vanilla name gets `[SuppressMessage("Style", "IDE1006", Justification = "Vanilla name (m_argv.c)")]` (SPEC §12 Q4). A new ported file goes in that list; new code anywhere else follows the Godot/.NET names.
- **Deviations from vanilla behaviour sit behind a named tweak flag** (SPEC §6.3), so pure vanilla behaviour stays testable.
- **The license is GPL-2.0-or-later.** Porting id Software or Chocolate Doom code is fine. Check license compatibility before adding any other dependency.
