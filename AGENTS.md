# IsoDoom

An isometric top-down remake of Doom in Godot 4 + C#. It loads the original WAD at runtime. The full design is in `docs/SPEC.md`. Read only the sections your task cites.

## Session workflow

Each session completes **one task** from `docs/TASKS.md`:

1. Read the task and the `SPEC.md` sections it cites.
2. Do the work. The task is done when its *Done when* criterion holds and all tests pass.
3. In `TASKS.md`: tick the task, and add any follow-up tasks you discovered under the right milestone.
4. When you make a design decision the spec doesn't cover, add it to the decisions log in `SPEC.md` §12.
5. Commit on a branch named after the task (e.g. `t1.2-wad-reader`).

## Commands

Run from the repo root. Versions are pinned in `docs/SPEC.md` §12; the .NET SDK comes from `global.json`.

- **Build:** `dotnet build IsoDoom.sln`
- **Test:** `dotnet test`. Tests that need a real WAD skip themselves without it (as in CI); see *Test data*.
- **Run:** `godot` opens the editor (F5 runs the main scene, currently the WAD viewer). `godot --headless --quit-after 60` runs the main scene headlessly for 60 frames; drop `--headless` for a window. On a fresh checkout, run `godot --headless --import` first.
  - Game arguments go after `--`: `godot -- -iwad wads/doom2.wad -file my.wad`. Without `-iwad` (or `ISODOOM_IWAD`), the IWAD search of `src/Wad/IwadLocator.cs` runs (saved path, working dir, `wads/`, `DOOMWADDIR`, Steam/GOG, …; SPEC §12) and a file picker opens when nothing is found. The shareware IWAD refuses `-file`, as in vanilla.
- **Level scene:** `godot -- --level E1M1` (or `--level MAP01`; IWAD as above) shows the map as a textured mesh through the game camera (T3.3: fixed iso, orthographic) instead of the viewer, and runs the sim on it (T4.7: a 35 Hz tic loop independent of the frame rate, one `ticcmd` per tic from the input, mobjs drawn interpolated between the last two tics; the camera follows the player mobj). Debug arguments: `--level-tweaks=topdown|vanilla` (the sim's tweaks and the commands built for them: twin-stick, or vanilla's facing-relative movement and turning keys; default `topdown`), `--level-camera=iso|overview|fly` (default `iso`), `--level-projection=ortho|perspective` (the game camera's; default `ortho`, SPEC §12 T3.3), `--level-pitch=DEG` (45–60, default 55), `--level-zoom=UNITS` (view height, 320–1600, default 640), `--level-cutaway=cut|dither|off` (the wall cutaway around the player under the game camera, SPEC §12 T3.4; default `cut`), `--level-cutaway-radius=UNITS` (default 80), `--level-cutaway-height=UNITS` (the cutoff above the player's feet, default 32), `--level-cutaway-cursor=on|off` (the cursor ground point cuts too; default `off`), `--level-cutaway-things=decor|all|off` (which billboards in front of the player the cutaway cuts as walls, SPEC §12 T3.4b; default `decor`: all but actors, so monsters, barrels and the player stay whole), `--level-cutaway-cap=dark|flat|off` (a raised floor cut by the cutaway shows its flat at the cutoff, darkened or not, instead of the void inside; SPEC §12 T3.4a; default `dark`), `--level-masked-back=mirror|off` (a masked middle on one side of a line only is also drawn from behind, mirrored; `off` = vanilla, one side only; SPEC §12 T3.1a; default `mirror`), `--level-view=top` (the overview camera straight down; default iso), `--level-focus=SECTOR`, `--level-tiling=size` (default `vanilla`), `--level-sector-floor=SECTOR:HEIGHT[,…]`, `--level-skill=1-5` (whose things are drawn as billboards, T3.5; default 3), `--level-sprite-tilt=0-1|off|half|full` (billboards turn towards the camera by this fraction of its elevation, SPEC §12 T3.6; default `full`), `--level-sprite-tilt-depth=upright|tilted` (default `upright`: a tilted billboard sorts as an upright one), `--level-sprite-shadow=off|blend|dither` (blob shadows under actors; default `off`), `--level-sprite-outline=off|INDEX` (a one-texel outline in palette index INDEX; default `0`, black), `--level-sprite-wall-pull=UNITS|off` (billboards are pulled towards the camera by the thing's radius, at most UNITS, so a wall the thing stands against behind it does not cut it, SPEC §12 T3.5a; default `16`), `--level-sprite-hidden=depth|upright` (with `upright`, a tilted billboard is also dropped whole when the level would hide its upright billboard whole, so monsters behind a wall no longer show their heads above it; costs about 3 ms a frame under lavapipe; SPEC §12 T3.6a; default `depth`), `--level-light=player|none|camera` (light diminishing, SPEC §12 T2.8; default `player`), `--level-light-origin=X,Y` (the player position for it, map units; default the free-fly pivot or the player mobj), `--level-light-near=UNITS` (player mode's shortest distance, default 80; 0 = the tables down to the player, T3.7), `--level-light-reference=UNITS` (none mode's distance, default 128), `--level-background=RRGGBB` (the void's colour; one in no palette, e.g. `00ff00`, makes cracks stand out), and `--level-screenshot=FILE.png` (capture and quit; needs a real renderer, e.g. the offscreen Xvfb + lavapipe command below; never commit the images).
  - **Level scene keys:** Tab cycles the game camera, the overview and the free-fly debug camera, Home puts the player (in free-fly the camera) at player 1's start, PgDn/PgUp load the next/previous map of the WAD, L cycles the light diminishing mode, X cycles the cutaway style (cut, dither, off), V the things it cuts (decor, all, off), T the sprite tilt (full, half, off), G the blob shadows (off, blend, dither), P the sprite wall pull (on, off), H the sprite upright hiding (depth, upright), M the one-sided masked middles from behind (mirrored, off), K the cutaway cap (dark, flat, off), F1 lists the controls, F3 hides the overlay (map, FPS, camera position in map units, the sector and subsector under the camera; with the game camera the player mobj (position, angle, state, sector), the tic, checksum and last `ticcmd`, and the cursor ground point, also marked by a ring). Game camera: the input actions build each tic's `ticcmd`, only while it is current: W/A/S/D (or the left stick) walk the player relative to the screen (Shift runs, the left-stick click toggles run; these are input actions in `project.godot`, T4.6), the mouse (or the right stick) aims, Ctrl+wheel zooms, O = orthographic/perspective. Free-fly: click to capture the mouse (Esc releases), mouse look, W/A/S/D move, E/Space up, Q/C down, Shift ×4, Alt ×¼, wheel = speed, Ctrl+wheel = FOV or ortho size, O = perspective/orthographic.
  - **Scripted input** (no keyboard needed): `--level-script="click; look 0 200; hold W 60; tap PageDown; print; shot FILE.png"` feeds the commands through `Input.ParseInputEvent` and quits (full list in `src/Game/LevelScript.cs`); put `--fixed-fps 60` before `--` for frame-exact movement. `mouse X Y` moves the cursor (viewport pixels; the headless viewport is 64×64) and `place X Y [ANGLE]` puts the player mobj at a map point (on the floor, no momentum, no collision check). `ticcmd [vanilla]` prints the `ticcmd` the builder (T4.6, `src/Game/TiccmdBuilder.cs`) makes from the input since the last tic for the player, with the twin-stick tweaks or vanilla's. **Tic scripting** (T4.7): `cmd FORWARD SIDE ANGLETURN [BUTTONS] [TICS]` queues raw `ticcmd`s (twin-stick: ANGLETURN = absolute angle × 65536 / 360, FORWARD thrusts north, SIDE east), `step TICS` runs TICS tics built from the input (keys held with `down`), `checksum` prints `leveltime`, `World.Checksum()` and the player mobj; with either in the script tics run only from the queue (35 Hz, the world holds still when it is empty), so `godot --headless --fixed-fps 30 -- --level E1M1 --level-script="cmd 50 0 16384 0 35; down W; step 35; up W; checksum"` prints the same checksum at any `--fixed-fps` (`sim live|scripted` switches, `tics N` waits N tics, `smooth FRAMES` prints the drawn player's step per frame). `visible [MIN]` prints how much of the player the game camera shows (% of its pixels; the script fails below MIN, default 25; needs a real renderer), `walkto X Y [STEP] [MIN]` moves the player in a straight line through walls checking that at every STEP units, and `tour [STEP] [MIN]` walks it to every sector's floor (T3.4: `--level-script="tour 32"` on E1M1 takes about a minute under lavapipe). `fov vanilla; view X Y ANGLE` puts the free-fly camera where a vanilla player standing at map point X, Y facing ANGLE (degrees) would see (eye level, vanilla's 90° field in a 16:10 window), for comparing with vanilla screenshots (with `--level-light=camera`).
- **Viewer check:** `godot --headless -- --viewer-check` walks every graphic and every lump in the viewer and checks the uploads; it exits 1 on a failure. With a real renderer it also compares every drawn pixel: run it windowed, or offscreen with `WAYLAND_DISPLAY= VK_DRIVER_FILES=/usr/share/vulkan/icd.d/lvp_icd.json xvfb-run -a -s "-screen 0 1280x720x24" godot -- --viewer-check`. Add `--viewer-screenshots=DIR` to save captures (never commit WAD-derived images).
- **Level check:** `godot --headless -- --level-check` loads every map of the IWAD in the level scene and checks the meshes, texture binding, per-sector data and thing billboards against the levels, plus a floor moved through the data texture; it exits 1 on a failure. With a real renderer (windowed, or offscreen as the viewer check) it also renders one map (`--level MAP`, default `E1M1`/`MAP01`) top-down, side-on at every axis-aligned wall (masked middles over their whole opening: texels, holes and the rows outside the texture) and obliquely at the moved floor, and the cutaway from the game camera's angle (a centre just behind and just in front of a tall wall, and just behind a raised floor: cut pixels show the background, or with the cap the raised floor's flat at the cutoff, the rest draw as with the cutaway off) and the things (each distinct sprite frame, rotation and mirror side-on, alone, with the outline; one without outline, and two with full tilt from the game camera's pitch, again 1:1; one from the game camera's angle over the floor; one moved in front of a wall, whose full-tilt billboard the wall must not cut; the widest one against a wall behind it, which the wall pull must keep whole, and behind a wall, which must still hide it; one behind a wall taller than it, whose tilted billboard peeks over the wall unless the upright hiding drops it, and partly hidden and in front, which the upright hiding must leave as they are; the tallest one with a cut centre behind it, behind and below it, and in front of it, cut as a decoration and kept as an actor), and compares drawn pixels with the CPU texel lookup and light mapping (about 30 s for DOOM1 E1M1 under lavapipe, 4 s for the synthetic IWAD). It also fails a map that takes over 1 s to load (SPEC §9) and prints the slowest.
- **Vanilla comparison:** `tools/VanillaRef/compare.sh DIR wads/DOOM1.WAD E1M1 "1056 -3616 90;1056 -3616 0" [--images]` renders each view (map X Y, angle in degrees, at eye level; walls, floors and masked middles, no sprites, ceilings or sky) with vanilla's renderer (doomgeneric, GPL-2.0, pinned and patched by `tools/VanillaRef/build.sh` into `~/.cache/isodoom/vanilla-ref`; a dev tool, never shipped) and in the level scene offscreen, and compares them pixel by pixel (SPEC §12, T2.9). DIR gets WAD-derived images: keep it out of the repo.
- **Synthetic IWAD:** `dotnet run --project tools/SyntheticIwad -- OUT.wad` writes a small IWAD of generated, non-id content covering every lump kind; CI runs the viewer check against it.
- **Export (Linux x86_64):** `mkdir -p export/linux && godot --headless --export-release "Linux" export/linux/IsoDoom.x86_64`. Needs the 4.7.2 .NET export templates in `~/.local/share/godot/export_templates/4.7.2.stable.mono/` (build the dev container with `INSTALL_EXPORT_TEMPLATES=true`, or see `.github/workflows/ci.yml`). Smoke test: `export/linux/IsoDoom.x86_64 --headless --quit-after 60`.
- **CI:** `.github/workflows/ci.yml` runs build + test, generates the synthetic IWAD, runs the viewer and level checks in the editor (headless), exports and smoke-tests the Linux build, runs both checks on the exported build under Xvfb + lavapipe, and uploads `export/linux/` as the `IsoDoom-linux-x86_64` artifact. Lint it with `actionlint` (in the dev container; it runs `shellcheck` on the scripts).

## Invariants

- **`Sim/` is deterministic** (so lockstep co-op is possible later):
  - pure C#, with no Godot types;
  - fixed-point/BAM maths only, no `float`/`double`;
  - no `System.Random`, wall-clock time, or iteration over `Dictionary`/`HashSet`;
  - the only input is a `ticcmd` per player per tic.

  The presentation layer converts to floats.
- **WAD data stays out of the repo.** All assets load from the user's WAD at runtime. `wads/` is gitignored.
- **Ported vanilla logic keeps vanilla names** (`P_Random`, `A_Chase`, `mobjinfo`), with a comment citing the source file (e.g. `// p_enemy.c`). This keeps it easy to diff against the original.
- **Deviations from vanilla behaviour sit behind a named tweak flag** (SPEC §6.3), so pure vanilla behaviour stays testable.
- **The license is GPL-2.0-or-later.** Porting id Software or Chocolate Doom code is fine. Check license compatibility before adding any other dependency.

## Test data

`wads/DOOM1.WAD` is the shareware v1.9 WAD (MD5 `f0cefca49926d00903cf57551d901abe`; set `ISODOOM_DOOM1_WAD=/path/to/DOOM1.WAD` to use one elsewhere). Tests that need it skip themselves when the file is absent.

`wads/doom2.wad` (any Doom II version; set `ISODOOM_DOOM2_WAD=/path/to/DOOM2.WAD` to use one elsewhere) enables the Doom II tests, which skip themselves without it.
