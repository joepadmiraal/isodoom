# IsoDoom

An isometric top-down remake of Doom in Godot 4 + C#. It loads the original WAD at runtime. The full design is in `docs/SPEC.md`. Read only the sections your task cites.

## Session workflow

Each session completes **one task** from `docs/TASKS.md`:

1. Read the task and the `SPEC.md` sections it cites.
2. Do the work. The task is done when its *Done when* criterion holds and all tests pass.
3. In `TASKS.md`: tick the task, and add any follow-up tasks you discovered under the right milestone.
4. When you make a design decision the spec doesn't cover, add it to the decisions log in `SPEC.md` §12.
5. Commit on a branch named after the task (e.g. `t1.2-wad-reader`).

Screenshots for the user to review go in `screenshots/TASK-topic/` (gitignored: they are WAD-derived), never only in a temporary directory, which the user cannot open.

## Commands

Run from the repo root. Versions are pinned in `docs/SPEC.md` §12; the .NET SDK comes from `global.json`.

- **Build:** `dotnet build IsoDoom.sln`. Every project takes its shared settings from the root `Directory.Build.props` (Q5: warnings as errors, and the SDK's analyzers in the build, `AnalysisMode` Recommended plus the `.editorconfig` style rules at warning), so an analyzer finding fails the build; `.editorconfig` lists each rule turned down and why (SPEC §12 Q5).
- **Test:** `dotnet test`. Tests that need a real WAD skip themselves without it (as in CI); see *Test data*. A test that asserts on wall time (SPEC §9's budgets) takes `[Collection(TimingGroup.Name)]` (T8.6a, `tests/IsoDoom.Tests/Support/TimingGroup.cs`): that collection runs alone, after the parallel tests. **Regression checksums** (T8.6, `RouteChecksumTests`, `tests/IsoDoom.Tests/Sim/RouteChecksums.cs`): every route of `tests/IsoDoom.Tests/Sim/Routes` and the IWADs' demos (DOOM1's, Doom II's as v1.9 and as `final`, TNT's, Plutonia's) play against the committed `Routes/checksums.txt` (`NAME TICS HASH…`: each tic's `World.Checksum()` and dump line chained into a 64-bit FNV-1a, folded to 8 hex digits after every 35th tic and the last; `iwad NAME MD5` lines name the IWAD the id IWADs' entries were recorded on, another version skips): the synthetic IWAD's and the test maps' always (CI, no WAD), the others with their WAD; a failure names the first second whose state differs. After a deliberate change to the sim, `ISODOOM_UPDATE_CHECKSUMS=1 dotnet test --filter "FullyQualifiedName~RouteChecksumTests"` rewrites the entries of the routes that ran (the rest are kept) and the change commits the file.
- **Format:** `dotnet format IsoDoom.sln` formats the code to `.editorconfig` (the Godot C# style guide over .NET's conventions; vanilla names stay, SPEC §12 Q3); `dotnet format IsoDoom.sln --verify-no-changes --severity warn` checks it, as CI does, naming included (Q4: `IDE1006` at warning; `dotnet format` reports a misnamed symbol but cannot rename it: rename it in the IDE). The one-time reformat is in `.git-blame-ignore-revs`: `git config blame.ignoreRevsFile .git-blame-ignore-revs` hides it from `git blame`.
- **Run:** `godot` opens the editor (F5 runs the main scene: the game, T7.1, at the title loop; with `--viewer` after `--`, the WAD viewer). `godot --headless --quit-after 60` runs the main scene headlessly for 60 frames; drop `--headless` for a window. On a fresh checkout, run `godot --headless --import` first.

P10: both take a PWAD set's folder before them (`scythe-map01-walk-exit`, `neis-e1m1-walk-exit`, `requiem-map06-line2610`: the set over its IWAD, `tools/RouteGen/PwadSet.cs`, the route's `pwad SET` header; written to `Routes/` unless OUT is given: the sets' go in `Routes/pwad/`), `ROUTEGEN_PWAD=SET` gives `--info`, `--probe`, `--monsters` and `--sight` the set, `SET-mapNN-brain` (Doom II sets) kills the map's Icon of Sin brain with a route event on the first tic, monsters on, to its `A_BrainDie` exit (`requiem-map30-brain` to the cast call, `scythe-map20-brain`: Scythe's MAP20 exits only so), and the walked exit's hints also take `walk:X,Y,TICS,SPEED` (straight, no planning: Requiem MAP01's run across its pit), `goto:X,Y`, `wait:TICS` and `exit:X,Y` (use the exit switch there, the route's end); the committed PWAD routes: each set's first map to its second (`SET-map01-walk-exit`, `SET-e1m1-walk-exit`; AV's, D2TWID's and Requiem's with hints), Requiem's text screens (`requiem-map06-line2610`, `-map11-line1477`, `-map20-line171`, `-map15-line2833`, `-map31-line1889`) and `requiem-map30-brain`, `scythe-map20-brain`. T10.7: both take `tnt-` or `plutonia-` before them for Final Doom's IWADs (`wads/` or `ISODOOM_TNT_WAD`, `ISODOOM_PLUTONIA_WAD`, played as `final`), and `ROUTEGEN_IWAD=tnt|plutonia` gives `--info`, `--probe`, `--monsters` and `--sight` Final Doom's `MAPxx` (M9: `doom-exmy-walk-exit`, `doom-exmy-lineK`, `doom-exmy-sectorK` on The Ultimate Doom's IWAD, `ISODOOM_DOOM_WAD` or `wads/doom.wad`, `retail`; the tools take its `ExMy` for E2–E4, or E1 with `ROUTEGEN_IWAD=doom`); a line route of a switch exit (11, 51) ends with the use; the walked exit also presses the nearest switch and crosses the nearest walk-over line within reach (none that closes or crushes) when neither the exit nor a key is, rides a lift it lowered, ends at the tic that leaves the level, and takes ordered hints (`_exitHints`: lines, `key:MT_…`, `tele:X,Y`; Plutonia's MAP01 needs them); `ROUTEGEN_DEBUG=1` logs why each line is out of reach, `ROUTEGEN_DEBUG="X,Y;…"` probes those points when it gives up. Committed: `tnt-map01-walk-exit`, `plutonia-map01-walk-exit` (their MAP01s to MAP02, with intermissions, wipes and songs against vanilla), `tnt-map06-exit` (a script: the lift to the exit), and the text screens' line routes (`tnt-map11-line667`, `tnt-map20-line1513`, `tnt-map30-line719` to the cast call, `tnt-map15-line1417`, `tnt-map31-line2708`, `plutonia-map06-line1260`, `plutonia-map11-line1171`, `plutonia-map20-line11`, `plutonia-map15-line1099`, `plutonia-map31-line1109`).

## Invariants

- **`Sim/` is deterministic** (so lockstep co-op is possible later):
  - pure C#, with no Godot types;
  - fixed-point/BAM maths only, no `float`/`double`;
  - no `System.Random`, wall-clock time, or iteration over `Dictionary`/`HashSet`;
  - the only input is a `ticcmd` per player per tic.

  The presentation layer converts to floats.
- **WAD data stays out of the repo.** All assets load from the user's WAD at runtime. `wads/` is gitignored.
- **Ported vanilla logic keeps vanilla names** (`P_Random`, `A_Chase`, `mobjinfo`), with a comment citing the source file (e.g. `// p_enemy.c`). This keeps it easy to diff against the original. The naming rules skip the ported files listed at the end of `.editorconfig` (all of `src/Sim` but its few files of our own); elsewhere a vanilla name gets `[SuppressMessage("Style", "IDE1006", Justification = "Vanilla name (m_argv.c)")]` (SPEC §12 Q4). A new ported file goes in that list; new code anywhere else follows the Godot/.NET names.
- **Deviations from vanilla behaviour sit behind a named tweak flag** (SPEC §6.3), so pure vanilla behaviour stays testable.
- **Godot values outlive the native calls that use them** (SPEC §12 T8.3b, T8.3d, T8.3g). Godot's C# binding keeps nothing alive across a call, and .NET's finalizer thread frees a wrapper's native data. So a `Variant` (anything but a scalar), a `Godot.Collections` collection, a `RefCounted`, or a `StringName` or `NodePath` (T8.3g: a `string` passed where one is expected is converted to a new one; use `StringNames.Get(name)` or a `static readonly` field) made or returned for one call is disposed (`using`) or held in a field, never left to the finalizer; a read-back `Image` or a `SurfaceTool` in a local is instead kept alive to its scope's end (`using var keep = GodotRefs.Keep(x)`, not disposed: disposing them was measured worse, SPEC §12 T8.3d). The helpers are in `src/Render/GodotRefs.cs`, and `GodotLifetimeTests` enforces the rule on the editor build's `IsoDoom.dll` (`dotnet build IsoDoom.sln` before `dotnet test`).
- **The license is GPL-2.0-or-later.** Porting id Software or Chocolate Doom code is fine. Check license compatibility before adding any other dependency.

## Test data
